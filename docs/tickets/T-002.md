# T-002 — User registration & authentication

**Depends on:** T-001
**Source:** TRD FR-01, TRD NFR-03

**Acceptance criteria:**
- Given a new email + password, registration creates a user record with a hashed password (bcrypt or equivalent); plaintext password never stored or logged.
- Given valid credentials, login issues a session/token; invalid credentials return a clear error without revealing whether the email exists.
- Given a registered user, password-reset email is sent; reset link sets a new hashed password.
- Given no session, access to report/claim pages redirects to login.
- Given duplicate registration with same email, registration is rejected with "email already registered."

**Definition of done:** Register, login, password-reset all work end-to-end; auth middleware protects report/claim routes.
